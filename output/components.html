04

Form elements

Selects, radios and checkboxes are custom-styled; the real inputs stay focusable and keyboard-operable. Tab through them to check the focus ring.

A required field takes .req after the label text and the required attribute on the control — the attribute is what a screen reader announces, the asterisk is only the visual half. A required dropdown opens on a value="" placeholder (“Select …”), so nothing is answered on the user’s behalf. Optional dropdowns keep a real default (“No — I have my own clubs”, “0”, “All categories”): that is an answer, not an empty state.

Cards

Overlay course card — .card.card--overlay

The course card the homepage and the detail pages' “also on the island” row use: the photograph is the card, and the name, price and button sit on it inside .card__overlay over a bottom-up gradient. Both badges move to the top right, the corner the type leaves free — .promo-badge--save as it is, .ratio__soon from a full veil to a chip. They never share a card: a course that is not open has no season saving. The pill is .pill--ghost, the rule takes --on-dark-rule, and the hover title turns --birdie, not --fairway, which a photograph would swallow. Laid out in .grid-2 on the homepage, which goes to one column at 900px because this card's type needs the width.

A course that has not opened adds .ratio--soon to the ratio box, as the second card below: the photograph drains to grayscale(1) so it reads as inactive beside the ones you can book, and the chip takes --sunrise, the logo yellow, with slate ink on it — yellow scores 1.34:1 on white and is never the type. It recolours the chip only; the geometry comes from .card--overlay.

Spec table

Three variants. Pick by what the rows contain, not by where they sit.

Default — label left, value right on one line. Reserved for money summaries (cart totals, checkout, order received), where right aligned amounts line up and can be scanned down the column.

.spec-table--stacked — label above value, both left aligned, each pair closed by its own rule. The house style for attribute lists: course specs, lesson details, club hire, contact details.

.spec-table--split — stacked, plus two columns above 900px, pairing left to right so rows 1 and 2 sit side by side. The default for attribute lists wherever the container is wide enough: course detail, the course list, lesson and club hire. An odd row count simply leaves the last pair alone on the left.

The threshold is the viewport, not the container, so check the column the table actually sits in before adding it. Contact keeps --stacked because its table is inside a 380px panel, which leaves about 130px per column — too narrow to split.

Interactive components

Shown in their default state. The navbar, drawer and lightbox on this page are the live components from components.css, driven by assets/js/main.js on real pages.

Navbar

Above 900px: brand left, inline menu centred, cart right. The menu takes flex: 1 so it centres in the space between brand and cart. Below 900px the menu is hidden and .navbar__menu-button appears instead, opening the drawer — the three remaining children then space out to hamburger / brand / cart. The active item is stamped by assemble.sh from the same page key that drives the drawer, so both stay in step.

The logo has two sizes. main.js adds .is-at-top to .navbar near the top of the page and removes it once scrolling starts, so the logo goes --logo-height-top → --logo-height over a 280ms height transition. The compact size is the CSS default, so a navbar with no script still looks correct. This first example is live — scroll the page and watch it shrink.

It enlarges below 4px of scroll and shrinks past 64px. The two thresholds are deliberate: resizing the logo changes the navbar's height, and a single threshold would sit inside that shift, so the state would flip back and forth and stutter. Any change to the logo tokens must keep the threshold gap wider than the height difference, and body keeps overflow-anchor: none for the same reason.

Scroll reveal

Blocks fade up as they scroll into view — this page included. It runs off a selector list in main.js (.section > .wrap > *, grid and split children, the page head, the course carousel, the contact banner), so pages get it without any markup attributes. Where a grid and its cards both match, only the deepest match animates. Siblings inside a grid or flex row stagger by 80ms up to 5 items; stacked content does not stagger, since it scrolls in one item at a time.

The .reveal / .reveal--in pair is applied by script and must never be authored in markup — the stylesheet hides nothing on its own, so a page whose JS fails still renders in full. Anything already on screen at load is skipped, so nothing flashes, and the whole effect is off under prefers-reduced-motion.

Not in this design: accordion and tabs. Add them to components.css and to this page in the same task if a future page needs them.
